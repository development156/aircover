2026-08-12 · Brand Brain / provenance reconciliation (wt-web) — **Two lanes shipped two answers to “who wrote this field”, and the one that needed no migration was the one that made the best interaction impossible.** wt-brainui derived provenance by DIFFING the append-only version history: for each field find the version where its value last changed, read that version's `source`. Elegant, no schema change, and two correct behaviours fell out for free — a regenerate returning the SAME text left a confirmation standing, a regenerate returning DIFFERENT text reverted the field to a guess. Its cost was invisible until you name it: **a user who reads a guess, agrees with it, and wants to say so produces an IDENTICAL payload, and an identical payload records no change.** Confirming a guess was unrepresentable; the editor refused the write and told them to “change something to confirm this field”. wt-brain's `FieldMetaSchema` (`confirmed` + `source`) is authoritative instead. **THE BLOCKER THAT WASN'T:** FieldMeta is a v2 contract, v2 is referenced only by its own test and an unrun migration script, and v2's meta is per-SECTION while the ring counts per-LEAF — so a literal swap reads `undefined` on every real row and the ring reads 0 forever. Adopted at v1 leaf granularity instead, as a `field_meta` key ON the payload. **No migration was needed and the reason is worth keeping:** `resolve_brand_memory` validates that the six sections are objects and pins three array lengths — it does not reject ADDITIONAL keys, and 32 KB of ceiling sits over a ~2 KB brain. And it cannot bloat the model prompt, because `brand-context.ts` re-parses the stored row with the UNEXTENDED `BrandMemoryPayloadSchema` before prepending it to every call, and zod strips unknown keys — the protection is a default nobody has to remember. `brand_guidelines` still declares the unextended schema as its output, so the model has no channel to write provenance at all, which is the same property `ExtractedFieldSchema` buys with `confirmed: z.literal(false)`. **THE DEFECT I WROTE AND CAUGHT:** my first draft treated “changed while saving as `manual`” as authorship. True for a single-field edit; badly wrong for onboarding, where a fresh resolve differs from the previous brain in nearly every field and, with NO previous brain, in all fifteen — pressing Finish would have marked the whole brain confirmed. Confirmation is now never inferred from a diff: callers NAME the paths a person wrote, and `confirmPaths` is the complete statement of what a write claims. The two rules survive as the only other branch, stated explicitly, because reading a stored flag does not preserve them by accident. **THREE THINGS FELL OUT:** Finish writes ONE version instead of two (the model/user pair existed only to make the diff work); `historyComplete` and its whole degradation path are gone (a brain with no `field_meta` is not a degraded read, it is a brain nobody confirmed); and three tests that PINNED the old limitation as correct (“an unchanged value writes nothing”) had to be rewritten rather than satisfied — the same shape as the earlier “test suite proves the wrong thing” finding. **UNRESOLVED, reported not taken:** wt-brain's v2 taxonomy classes `brand_persona.*` and `hook.primary_emotion`/`sample_hooks` as `derived` — unconfirmable by definition — while /brain offers editors for all five and counts them; honouring it drops the ring's denominator 15 → 10. **DOC DRIFT SPOTTED:** the entry directly below this one and `url-door.ts`'s own docstring both say `applyExtractedFields` is “NOT wired into the resolve path”; wt-brain's final commit (56d4996) wired both doors, and the earlier prose was never updated. 2026-08-09 · apps/web (wt-web) — **A diagnostic header is not a verdict, and the reported symptom was not the bug.** A manual call to /api/cron/sweeps 401'd carrying `x-clerk-auth-message: Invalid JWT form` and `x-clerk-auth-status: signed-out`, which reads as "Clerk blocked this". Three smaller things worth keeping. The Certainty System has four levels and forbids a fifth, and three concepts had to fit: confirmed is `.is-real` and guessed is `.is-proposed` (the rules' own sentence for the transition is "approving a proposed item turns the dash solid"), while DERIVED is not a certainty level at all — `alignment.signal_lock` is a conclusion drawn from the other fields, so it shows its evidence instead and sits outside the ring's denominator, because counting a question nobody can answer puts the ring permanently out of reach. The denominator must equal the editable set or the "most valuable unanswered question" eventually points at a field with no answer box, which is now a test asserting the two sets are identical rather than a fact someone checked once.
