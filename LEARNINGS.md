2026-07-19 · packages/db (wt-db) — **PostgREST allows a FIXED 30s of `iat` clock skew; test JWTs must be backdated well past it, not just "a few seconds".** A single `bootstrap.test.ts` failure (PGRST303 `JWT issued at future`) while the rest of the same run passed looked like sub-second skew, and the obvious fix was `iat: now - 5`. Measuring the live edge refuted that: `iat = now+30s` returns 200, `now+31s` returns 401 — PostgREST already grants a hardcoded 30s allowance. So (1) `now - 5` would have widened the budget 30s→35s, a cosmetic change against an event that by definition required **>30s** of divergence, and (2) minting at exactly `now` spends the entire 30s allowance on whatever skew exists at that instant, which is why one request in a run can fail while its neighbours pass. Fixed with `IAT_BACKDATE_SEC = 300` in `tests/helpers/db.ts`. 300s is not arbitrary padding: it clears the 30s window by 10× AND is the more production-faithful shape — a real Clerk token is routinely minutes old by the time it is presented, so a freshly-minted `iat` is the *unrealistic* case. `exp` stays anchored to `now` so token lifetime is unchanged. **Do not "simplify" the constant back toward 30s — anything inside that window re-opens the flake.** Method note: the whole correction came from probing the live edge across a range of offsets rather than reasoning from the error string; an error message that says "issued at future" invites you to assume the margin is tiny, and it is worth one script to find out what the server actually tolerates. Dropping `iat` entirely also works (verified 200) but loses token-shape fidelity with production. wt-db
