# apps/web

Follow the **sahoda-ui** skill. Tokens only (no raw hex — import `@sahoda/shared/tokens.css`).
Server actions for all mutations. `data-guide="…"` anchors on anything a tour targets. All states
ship with the component (hover/active/disabled/focus/loading/empty/error). Verb-first
sentence-case copy; `tabular-nums` for all credits/money/metrics.

- Import contracts/types from `@sahoda/shared` only — never redefine them here.
- Model calls go through server actions → `@sahoda/mesh`; never call a provider from the client.
- Playwright `@smoke` on the golden paths. Costs shown before any spend.
- **Dark accent-on-tint:** never pair `text-accent` on a `bg-tint-50/100` surface — in dark, `--t50/--t100` stay warm-light while `--acc` flips to Orange300 (~1.7:1). Add a `dark:bg-s2` surface swap (pattern: `bg-tint-50 text-accent dark:bg-s2`). See `empty-state.tsx`, `nav-item.tsx`, `workspace-switcher.tsx`.
- **…and give the swapped surface an EDGE.** The pattern above is right about contrast and, until 2026-08-22, landed every element that used it on a fill that separated nothing: `--surface-2` was `#17171a` in dark, which is `--surface` exactly. MEASURED: 117 of 120 dark frames carried at least one invisible fill. The token now has a real step (docs/26 §2.1) but the step is 1.04:1 — chrome, not separation — so anything that must read as a distinct object still carries `surface-ring` or `surface-ring-firm`. **`bg-s1` is never a fill**: `--s1` IS `--canvas`, the same `#ffffff` as `--surface` on light.
- **A choosing surface shows the name and the price; explanation goes in a drawer, not inline.** Founder's ruling, 2026-09-06, comparing `/connections`' right-hand "Details" panel against `/studio`'s inline wall of prose on a settings pill. Use `components/ui/drawer.tsx` only, per `components/connections/channel-details.tsx`. See docs/37 §15.
- **`backdrop-filter` makes an element a containing block for `position: fixed` descendants — so nothing that must cover the VIEWPORT may render inside a `glass` element.** MEASURED 2026-08-25 in Chromium at 1879x1007: the command palette's `fixed inset-0` overlay, rendered inside `<header className="glass">` (`blur(20px) saturate(1.6)`, 60px tall), laid out as **1834x137 at (45, 0)** instead of the full viewport. Its scrim therefore covered a strip across the top and the page beneath was never dimmed. Reported as THREE separate defects — a "black background bug", "no difference contrast in background and foreground", and a panel that would not line up — every one of them this single fact, and it survived three passes of careful measurement because each reproduction rendered the palette at body level, where the trap does not exist. The fix is a portal to `document.body` (`command-palette.tsx`), not removing the blur. `glass` is on the topbar, the rail and the bottom bar, so **any overlay, dropdown, popover or tooltip added to one of those must be portalled**; `palette-portal.test.tsx` asserts it for the palette and is the pattern to copy.
